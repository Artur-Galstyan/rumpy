# 012 — add

## One pair at a time

A reduction returns one result for the whole array. Elementwise addition instead
returns one result for each matching pair of elements. The output keeps the input shape.
This is the first binary array operation. Broadcasting comes later.

Write this function in `exercises/04_elementwise/012_add.rs`:

```rust
pub fn add(a: &Array, b: &Array) -> Array
```

NumPy API: <https://numpy.org/doc/stable/reference/generated/numpy.add.html>

## Supported contract

- Both inputs are valid owned, contiguous, row-major `f64` arrays. Require identical
  shapes, including rank, axis order, and singleton axes. Equal element counts alone
  do not suffice. Check this before an empty-input shortcut or pair traversal.
- If shapes differ, panic with exactly `add requires identical shapes`. Even a
  NumPy-broadcastable pair is outside this lesson. The panic avoids a new shared
  error type or any change to your library scaffold.
- At flat position `i`, compute the ordinary Rust `f64` expression `a[i] + b[i]`.
  Do not reduce the values, reorder them, or add an initial accumulator.
- Return a new independent array with the same shape and one result per pair.
  Leave both input shapes and every input data bit unchanged. The same array can
  supply both arguments. Separate calls must own separate output storage.
- Shape `[]` means one scalar plus one scalar. A zero-length axis means no pairs.
  Preserve equal empty shapes, even `[usize::MAX, 0]` or `[0, usize::MAX, 2]`.
  Work from the stored slices. Do not traverse axis lengths or recompute unchecked products.

No broadcasting, axis parameter, `out`, `where`, dtype conversion, views, integer
arithmetic, or operator overload belongs to this task. It does not depend on argmax.

## Examples

```text
shape [3]:
[ 1.0, -2.0, 3.5 ]
[ 4.0,  8.0, 0.5 ]
-------------------
[ 5.0,  6.0, 4.0 ]   shape [3]

shape [2, 2], stored row-major:
[1, 2, 3, 4] plus [10, 20, 30, 40] gives [11, 22, 33, 44].

shape []: 2.5 plus -4.0 gives a scalar Array containing -1.5.
shape [2, 0, 3]: two empty inputs give an empty Array with shape [2, 0, 3].

Shapes [2, 3] and [3, 2] must panic, despite equal storage lengths.
Shapes [] and [1] must panic, even though NumPy can broadcast them.
```

## Floating-point details

Use one `f64` addition for each pair under the normal rounding mode.
The tests compare non-NaN results by their bits. They compare NaNs only by `is_nan()`.
NaN payloads and signs in the output are not specified. Input NaN bits must remain intact.

Positive infinity plus a finite value remains positive infinity. Opposite infinities
produce NaN. Finite overflow can produce infinity and is not a shape error.
Tiny subnormal values remain part of the calculation. Rounding can discard a small
addend, so the output need not equal the exact real-number sum.

Negative zero plus negative zero produces negative zero. Mixed zero signs produce
positive zero. Exact cancellation of opposite finite values produces positive zero.
Do not seed each pair with positive zero: that changes the negative-zero case.

## Rust tools

You may use `shape()`, `as_slice()`, `size()`, `Array::from_vec`, vector methods,
loops, or standard iterators. `Iterator::zip` pairs two iterators but stops at the
shorter length. It does not validate shape equality. The valid `Array` inputs
already guarantee that each stored slice matches its own shape.
